# 后端优化待办

这份清单用于记录 Heal View 服务端的性能、稳定性、安全和可维护性优化方向。当前先建立问题边界和验收方式，避免在缺少数据时直接改动数据库查询或认证行为。

## 当前状态

- 当前后端以 Express、Node.js 内置 SQLite 和进程内缓存为核心，面向单用户个人部署。
- 导入、认证、日期、日汇总、时间序列、运动记录、睡眠和体重接口均已接入基础错误处理与参数校验。
- 本文档优先记录“首次登录进入看板变卡”的现象调查，其他项目按实际需求推进。

## P0：首次登录进入看板变卡

- [ ] 建立首登请求耗时基线。（记录登录、认证状态、日期列表、日汇总批处理、看板首屏接口的服务端耗时、SQL 次数和返回体大小。）
- [ ] 确认冷缓存与热缓存差异。（分别在服务重启后的第一次登录、刷新页面和第二次进入看板时采样，区分数据库查询慢、接口排队和前端渲染慢。）
- [ ] 梳理首次进入看板的重复请求。（重点检查登录后的 `auth/status`、`dates`、多日期 `summary`、当前日期数据和个人数据是否重复读取。）
- [ ] 评估日期列表训练日期判定策略。（当前日期列表返回后，前端会按最多 8 个日期一批读取日汇总；需要评估服务端一次性返回训练日期、增加聚合接口或延迟加载的收益。）
- [ ] 检查同步 SQLite 查询对 Node.js 事件循环的阻塞。（重点关注日汇总多次 JSON 查询、运动记录和体重数据查询在数据量增长后的耗时。）
- [ ] 确认图表资源初始化是否与 API 请求竞争主线程。（若服务端耗时正常，再结合浏览器 Performance 检查 ECharts 初始化和多图同时渲染。）

### 当前假设

1. 首次访问时进程内缓存为空，日期列表和日汇总查询需要完整执行；后续访问命中缓存，因此体感明显变好。
2. 日期侧栏为了识别训练日期会触发多次日汇总请求，可能与看板首屏请求重叠。
3. `node:sqlite` 的同步查询不会创建额外线程；当多个请求同时进入时，查询会依次占用服务端事件循环。
4. 也可能存在前端首屏图表懒加载、ECharts 初始化或浏览器解码造成的卡顿，不能只凭体感将问题归因于后端。

### 建议验收

- 冷启动首次登录和热缓存再次进入的接口耗时均有可复现记录。
- 首次进入看板的重复请求数量明确，关键请求不再无必要重复执行。
- 在代表性数据量下，首屏接口的 P95 耗时和浏览器交互延迟有对比数据。
- 优化不能改变日期选择、训练日期识别、认证跳转和图表数据结果。

## P1：查询与缓存

- [ ] 为缓存键、TTL、失效条件和缓存命中率建立统一说明与日志。
- [ ] 检查日期、汇总、时间序列和体重查询是否存在可合并的 SQL 或重复 JSON 解析。
- [ ] 用 `EXPLAIN QUERY PLAN` 检查主要查询，补充必要的复合索引；索引改动需要用导入数据量验证写入成本。
- [ ] 评估大日期范围和大量运动记录下的分页、限制和响应体大小。
- [ ] 导入或清空数据后统一失效相关缓存，避免短时间内读取旧数据。

## P1：接口稳定性与资源生命周期

- [ ] 统一控制器的成功、空数据、参数错误、未授权和服务端错误响应格式。
- [ ] 为上传、解析和入库流程补充请求大小、超时、取消和并发限制。
- [ ] 检查数据库初始化失败、连接关闭、进程退出和导入中断时的恢复行为。
- [ ] 为慢查询、未捕获异常和导入失败建立结构化日志，避免只依赖 `console.error` 文本。
- [ ] 评估健康检查是否需要区分进程存活、数据库可用和缓存状态。

## P1：安全与数据边界

- [ ] 为认证接口增加失败尝试限制、必要的安全响应头和 Cookie 配置检查。
- [ ] 复核 CORS、上传文件类型/大小、压缩包路径和临时文件清理边界。
- [ ] 检查错误响应是否可能泄露本地路径、SQL、导入文件名或个人健康数据。
- [ ] 明确进程内 session 在重启、多进程和反向代理场景下的限制，并写入部署文档。

## P2：测试与工程质量

- [ ] 为控制器参数校验、认证状态、缓存失效和导入失败路径补充边界测试。
- [ ] 增加代表性 SQLite 数据集的查询性能基线，覆盖冷缓存和热缓存。
- [ ] 增加 API 请求级测试，验证认证、错误状态码、响应结构和缓存行为。
- [ ] 在 CI 中加入服务端测试、API smoke test 和必要的数据库迁移/初始化检查。
- [ ] 记录后端优化的动机、数据规模、验证命令、耗时变化和遗留风险。

## 建议推进顺序

1. 先给首次登录链路补齐耗时和请求计数证据，确认卡顿发生在服务端、网络还是浏览器主线程。
2. 再处理日期训练判定和看板首屏的重复查询，优先减少冷启动工作量。
3. 接着检查慢 SQL、缓存失效、导入资源边界和认证接口保护。
4. 最后补齐性能基线、API 级测试和部署约束文档。
