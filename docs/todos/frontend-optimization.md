# 前端优化待办

这份清单用于记录 Heal View 当前前端优化方向。每一项先明确问题、目标和验收方式，再进入实现，避免为了“优化”而进行没有收益的改动。

## 本轮已完成

- [x] 页面路由级懒加载，降低首屏入口脚本体积，并避免登录页初始化仪表盘布局。
- [x] 复用短时间内的认证状态请求，减少重复鉴权请求。
- [x] 日期列表汇总请求改为限量并行批处理，缩短历史日期较多时的等待时间。
- [x] 图表 ECharts 实例、Resize 监听、延迟初始化任务和异步回调增加卸载清理。
- [x] 增加统一异步状态组件，开始收敛 loading、empty、error 的展示方式。
- [x] 移除 Element Plus 图标全量注册，改为组件级按需导入。
- [x] 保持 ECharts core 按需注册，并结合图表懒加载避免登录页加载图表资源。

## 优先级说明

- **P0**：影响使用体验、稳定性或后续开发效率，应优先处理。
- **P1**：能明显改善性能、可维护性或交互体验。
- **P2**：体验增强或结构性改进，可结合功能迭代推进。

## P0：基础体验与稳定性

- [ ] 梳理全局页面加载、接口加载、空数据和错误状态，统一反馈方式。
- [ ] 检查窄屏和小窗口下的布局，重点关注顶部导航、日期选择器、图表和个人配置页。
- [ ] 为路由页面补充基础级别的组件测试或页面行为测试。
- [ ] 清理页面中的硬编码文案，确保新增功能完整接入中英文国际化。
- [ ] 统一按钮、表单、卡片、标题和间距的视觉规范，减少页面之间的样式差异。

## P1：性能与资源加载

- [x] 按路由拆分页面和较重组件，减少首屏 JavaScript 体积。
- [x] 评估 ECharts 按需引入和图表组件加载策略，降低初始加载成本。
- [x] 检查图表监听器、定时器和请求的生命周期，避免路由切换后继续占用资源。
- [x] 为日期切换、筛选和多日对比增加请求去重、取消过期请求或合理缓存。
- [ ] 检查生产构建产物体积，建立一次构建体积记录，后续用数据判断优化收益。

## P1：组件与状态管理

- [ ] 提取页面中重复的筛选、日期选择、加载和错误处理逻辑。
- [ ] 梳理 Pinia store 的职责，区分服务端数据、页面状态和纯 UI 状态。
- [ ] 为图表组件统一数据输入、空状态、主题切换和窗口尺寸响应接口。
- [ ] 减少跨层级样式覆盖，明确全局样式、布局样式和组件局部样式的边界。
- [ ] 评估个人配置、导入、报告等页面是否需要统一的页面容器组件。

## P2：交互与可访问性

- [ ] 补充键盘操作、焦点状态和表单错误提示。
- [ ] 检查图标按钮的 aria-label、链接打开方式和颜色对比度。
- [ ] 优化移动端的导航、筛选器和图表横向浏览体验。
- [ ] 为关键图表补充可读的摘要或表格化信息，降低仅依赖视觉图表的门槛。
- [ ] 增加用户偏好记忆，例如最近使用的语言、主题、日期范围和视图模式。

## P2：工程质量

- [ ] 引入前端代码格式和静态检查，并接入提交前或 CI 检查。
- [ ] 建立关键页面的桌面端和移动端截图基线。
- [ ] 为健康规则、数据格式化和图表数据转换补充边界测试。
- [ ] 记录每次优化的动机、改动范围、验证方式和结果。

## 建议推进顺序

1. 先完成全局状态、响应式布局和国际化清理，建立一致的使用基础。
2. 再处理路由拆分、ECharts 资源和请求生命周期，降低性能风险。
3. 接着收敛组件与状态管理，减少后续功能开发成本。
4. 最后持续补充可访问性、工程检查和性能基线。
